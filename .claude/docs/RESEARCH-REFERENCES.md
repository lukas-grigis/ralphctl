# Research References

Every external source the prompt layer and harness design rest on, with what each one actually
establishes, where it is used, and its verification status. All entries below were verified against the
live originals on **2026-07-26/27** (existence, authorship, and claim fidelity checked by fetching each
source; attribution defects found in that audit have been fixed in the citing files). The rows added by
the research-adoption sweep were verified the same way on **2026-08-04**. The rows added by the
blocked-task-visibility sweep (the HiL-Bench row, the "Evaluated and NOT adopted" additions, and the
second banned-citation entry) were verified the same way on **2026-09-10**. The rows added by the prompt
and agent audit (vendor prompting guides, the swap-and-agree judge paper, the sub-agent docs) were
verified by fetching each page on **2026-09-29**; where a page supports only part of a claim, the row says
so. The rows added by the vendor-neutral prompt pass were re-fetched on **2026-10-05**; items without a
re-fetched quote sit under Engineering judgment. The rows added by the
vendor-guidance pass (Haiku 5.5, GPT-6, Fable 5.1, Opus 5.5 and Sonnet 5.5 guides, the Claude Code review
post, Grok project rules) were fetched on **2026-10-16**. The rows added by the provider pass (vendor
memory, verify-log truncation, readiness context-file loading, the Codex review rubric) were fetched on
**2026-10-30**. A citation-fidelity audit re-read the arXiv full text behind the rows that quote numbers
and corrected the attributions it found wrong, also on **2026-10-30**.

Maintenance rules:

- A claim cited anywhere in `src/` or `.claude/` should have a row here — add the row when adding the
  citation, with a URL or arXiv ID. URL-less citations are how fabricated references slip in.
- Descriptive findings (what files/agents typically look like) must not be cited as prescriptive
  recommendations — say "informed by", not "recommends", unless the source actually recommends.
- Re-audit on model bumps: several rows encode model-capability assumptions (long-context behaviour,
  judge reliability) that shift with each generation.

## Engineering judgment (no external source)

Decisions from the prompt and agent audit that no fetched source backs. They are listed so they are not
mistaken for researched ones; each is a call to revisit if a measurement contradicts it. Fixes that rest on
an internal contradiction in the code (a placeholder checkpoint no code detects, an example value that
fails schema parsing, an output path that bypasses a confirm gate) are code facts and are not listed.

- **Prompt-only verbatim gate.** The Fable 5 guide recommends a send-to-user tool; a prompt telling the
  model to show the document as its own message before the question is our substitute. The harness-side
  full-render review gate is the layer that does not depend on provider rendering. Reproducing the
  same-turn question-rendering problem in a live provider session has not been done.
- **Never substitute a summary, diff or pointer; re-present in full every round.** The cited source only
  supports being explicit about wanted behaviour.
- **Validation checklist runs before presenting, not after approval.** A post-approval fix produces a
  document nobody saw.
- **Numbered-list fallback when the runtime has no structured question tool.** The Codex prompting guide
  was fetched and addresses tool preference, not this fallback.
- **No `draft.md` step in the approval gate.** The audit proposed one as belt-and-braces; it was not adopted
  because the harness-side render covers the same risk.
- **Caps kept for schema-enforced fields, secrets, repo writes and destructive git.** The emphasis sweep
  removes shouty emphasis elsewhere; where to stop is our call.
- **Comparing hand-copied rules across the two evaluator templates** as the contradiction-detection
  method.
- **Two-revision bound on the reproduce loop.** No source gives a number.
- **Tie fallback to the existing quality ordering** when the swap-and-agree judge disagrees.
- **Applying GPT-5-specific and Opus-4.x-specific guidance to all five providers.** The vendor pages
  describe their own models.
- **Stop-and-report applied to every implement run**, not only xhigh/max effort, on the reasoning that the
  evaluator leaf is the independent review.
- **`reset --hard` and force-push in the reversibility rule.**
- **Untrusted-data notice sentence, and no escaping of closing tags in `substitute()`.** Most inputs are
  operator-authored; the marker line gives most of the value at a fraction of the surprise.
- **Rejecting an evaluator-skip path until an eval exists.**
- **Deleting the planner agent**, keeping the reviewer on a lighter model tier than the implementer, and
  leaving `effort:` out of agent frontmatter. The sub-agents docs only confirm that the field exists.
- **Prose git bans in agent bodies, not enforced by a hook.** The memory docs say a `PreToolUse` hook is the
  enforcing mechanism; none is configured, so the ban is a known gap rather than a decision.
- **Deleting the stash recipe from agent memory**, based on repeated incidents in this repo.
- **Session-label removal** from prompt comments: a project rule, not researched.
- **Observation outlet without a severity throttle.** The evaluator may record out-of-scope observations in
  the signals file; no filter on their severity. No fetched source backs the shape.
- **Vendor-neutral tool vocabulary.** Templates name actions ("read the file", "run the command"), not a
  provider's tool names; fenced by `prompt-hygiene.test.ts`. A product decision across five providers.
- **Verdict semantics live once in `evaluator-grading-rules.md`.** Kept as the single place for cheap A/B
  tuning; unmeasured.
- **Untrusted marker not applied to decision-bearing journals.** Wrapping the progress journal and decisions
  as "data, not instructions" would undercut the two-kind learnings rule; they stay operator-owned.
- **Unsure whether a defect is pre-existing: grade it as the change's own.** The review post tags pre-existing
  findings without saying how to break a tie; the default keeps the carve-out from becoming a way to wave
  defects through.
- **Not changing long-context ordering.** Lost in the Middle is cited only by the existing tail-compression
  in `compress-section.ts`; keeping head plus tail there, and 'reference data first, query last', were audit
  proposals that no commit on the branch implemented. Command output (verify logs, reproduction runs) does
  keep head plus tail — see the Codex prompting guide row.
